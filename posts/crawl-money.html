Crawl money, fast pages: indexing routines and the LCP-cost of slow ads

Money math: a page that never gets indexed earns nothing; a page indexed but slow earns half of what the auction would have paid. Both are free to fix on a static site.

Updated Nov 5, 20267 min read

Two commas decide your revenue: the one after 1,000 in your traffic numbers, and the RPM after it. The first comma is about crawlers. The second is about milliseconds. Handle them in that order.

Get indexed in days, not months

  1. Submit the sitemap in Search Console the same hour the site ships — this repo's sitemap.xml is already wired for that.
  2. Request indexing for any strong new URL via the URL Inspection tool. It's the single most underrated lever; a fresh personal site typically sees early impressions within 48–72 hours.
  3. Link new posts from the homepage. Every homepage link is a fresh crawl path — deep pages with no internal links starve.
  4. Publish on a schedule. Crawl patterns learn your cadence; weekly beats sporadic bursts.

Why every 100ms of LCP costs ad money

Auctions are timed. When the ad script requests units late — typically because the main content blocked rendering — the number of advertisers eligible in real-time bidding shrinks, and the clearing price drops. On top of that, delayed layouts physically shift units off-screen and tank the exact viewability metric priced into the auction.

Static hosting removes the server hop, this theme inlines zero web fonts, and every ad container reserves its height — so layout never jumps when a creative loads.

The built-in speed discipline in this repo

  • ads.js initializes slots 300px before they enter the viewport — requests fire early, render never blocks text.
  • System font stack, no CSS framework: a post page ships ~10KB of styling.
  • GitHub Pages serves on a CDN with correct caching headers by default.
  • .nojekyll skips (Jekyll) processing so every asset is byte-perfect.

Measure both commas weekly

Search Console for impressions and average position; PageSpeed Insights or the Web Vitals extension for LCP/CLS/INP; the AdSense reports split by unit for eCPM movement. One dashboard row per metric per week — that's the entire growth loop for a display-revenue site.
